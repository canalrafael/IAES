Context & Motivation

  • Mixed-Criticality Systems (MCS): Integrating safety-critical and best-effort applications on a single MPSoC platform.
  • Improves efficiency through shared resources (LLC, System Bus).
  • Problem: Contention introduces complex cross-core interference and unpredictable timing behavior.

Microarchitectural Side-Channel Attacks

  • Malicious actors exploit shared resources to induce interference.
  • Speculative Execution: Spectre, Meltdown.
  • Cache-based Attacks: ARMageddon (Prime+Probe, Flush+Reload).
  • Impact: Compromises confidentiality and disrupts timing guarantees (essential for real-time systems).

The Challenge

Why are current solutions insufficient?

  • Hardware Isolation: Static partitioning (e.g., Cache coloring) cannot fully isolate critical resources like LLC.
  • Software Monitoring: Heavyweight OS interrupts introduce non-deterministic overheads, breaking real-time guarantees.
  • AI-based Security: Often rely on dedicated NPUs/GPUs, increasing cost, power consumption, and memory footprint in embedded COTS platforms.

Proposed Architecture (IAES)

A lightweight, deterministic run-time monitoring architecture.

  • Integrated at the Hypervisor Level (Bao Hypervisor, ARMv8 EL2).
  • Monitors per-core execution without modifying guest software.
  • Protects secure domains (FreeRTOS) from untrusted domains (Linux).

Hardware Performance Counters (HPCs)

Used as low-overhead sensors to capture physical footprints.

  • Monitored Events: Cycles, Instructions, Cache Misses, Branch Misses, L2 Accesses.
  • Derived into robust ratio signals (IPC, MPKI, Branch Miss Rate, L2 Pressure).

Temporal Feature Engineering

  • Interference is bursty and irregular. Simple mean shifts are insufficient.
  • Sliding Window: (W = 10 samples) to capture short-term variability.
  • 12D Feature Vector: Mean, Standard Deviation, and Temporal Delta for each of the 4 ratio signals.
  • Z-score normalization ensures robustness across workloads.

TinyML Detection Model

  • Multi-Layer Perceptron (MLP): 12 → 16 → 16 → 1 topology.
  • Executes inside the bare-metal hypervisor via a dedicated timer interrupt (200ms).
  • O(1) Complexity: Input-independent execution path, no dynamic memory allocation.
  • Preserves strict Real-Time constraints.

Evaluation Methodology

  • Platform: Raspberry Pi 4 Model B (Quad-core Cortex-A72).
  • Dataset: Over 12 million PMU samples (300+ hours).
  • Scenarios: Benign benchmarks vs. Attack Interference (Spectre, ARMageddon, Meltdown-like).

Offline Training Results

  • High statistical overlap between high-load benign tasks and interference.
  • Model successfully learns the non-linear boundary.
  • Best Operating Point (τ=0.90):
    • Recall: 98.73%
    • False Positive Rate (FPR): 2.14%

Real-Time Deployment Performance

  • Accuracy: 97.94% overall recall, 2.72% FPR.
  • Hardware-Aware Metrics:
    • Footprint: ~6.0 KB static memory (1.94 KB ROM + 4 KB RAM).
    • Inference Cost: 464 MAC operations.
    • Latency: < 1 μs per inference.
  • Negligible timing interference with real-time deadlines.

Future Work

  • Adaptive Inference: Implement Early-Exit Neural Networks (EENNs) to dynamically adjust computational depth.
  • Closed-Loop Mitigation: Trigger hypervisor-level actuations (e.g., bandwidth throttling, QoS regulation) when attacks are detected.
  • International Collaboration: Cotutela program at Scuola Superiore Sant'Anna (Italy) starting in 2027.

Conclusion

  • IAES demonstrates that highly accurate, AI-based microarchitectural security is feasible on resource-constrained embedded platforms.
  • Operates completely within the hypervisor, avoiding OS dependencies and dedicated accelerators.
  • Establishes the foundation for future AI-driven resource management in Real-Time Systems.
